# Tauri Backend + WASM Core — Gotchas

## Rust String Lengths

`.len()` is **byte count**; one Chinese char = 3 bytes. Use `.chars().count()` for character comparisons and pattern-length ranking. **Exception**: `String::with_capacity(n)` takes bytes — `.len()` for capacity hints is correct and must NOT be changed to `.chars().count()` (that would under-allocate). Affects `dictionary_commands.rs`, `lookup_index_engine.rs`, `wasm-core/src/number_processor.rs`, `two_phase.rs:select_best_results()`, `matcher.rs` (lookahead fast-path), `lib.rs` (checksum + memory estimate).

## WASM-Only Symbols Cause SIGABRT on Native Tests

`web_sys::console` (`log_1`/`error_1`/`warn_1`) and all `js_sys::*` use `#[rustc_nounwind]` FFI — panicking aborts the entire test process (not catchable). Gate every call with `#[cfg(target_arch = "wasm32")]`. Rules:

- `#[cfg(debug_assertions)]` alone is NOT sufficient — debug native builds satisfy it.
- `Drop` impls: use `#[cfg(all(debug_assertions, target_arch = "wasm32"))]`.
- When gating a `pub fn`, also gate its `pub use` in `mod.rs` AND any `#[wasm_bindgen]` wrapper in `lib.rs`.
- `js_sys::Date::now()` for timestamps: fallback `let version_id = 0u64;` on non-WASM.
- Inline `#[test]` functions calling WASM-only methods must be `#[cfg(target_arch = "wasm32")]` gated on the entire `fn` — an ungated test blocks ALL `cargo test` compilation for the crate.
- `let foo` only referenced in a `#[cfg(wasm32)]` block → gate the declaration too: `#[cfg(target_arch = "wasm32")] let foo = expr;`.

## Rust Arithmetic

- **`hash.abs()` panics on `i32::MIN` in debug builds**: wrapping arithmetic can produce `i32::MIN`; `.abs()` overflows. Always use `.wrapping_abs()`. (The hash that hit this, `generate_content_hash`, was deleted 2026-10-03; the rule stands for any hash-then-abs code.)
- **`u64` timestamp subtraction**: `SystemTime::now()` is not monotonic on macOS. Use `.saturating_sub()` to avoid underflow. Affects `emit_poisoning_event` in `dictionary_commands.rs`.
- **Longest-match loops: use `>=` not `>`**: `if sequence.len() >= longest_length` allows multiple same-length patterns (last successful converter wins). `>` silently drops all but the first.

## WASM `&mut self` Borrow Rule (Rust 1.84+)

**Zero JS interop inside any `#[wasm_bindgen] &mut self` method body** — `serde_wasm_bindgen::to_value`, `js_sys::Array`, and `web_time::Instant::now()` all call into JS while `RcRefMut<T>` is live, firing `hint::assert_unchecked` in `alloc/src/rc.rs` → panic → `borrow_mut_count` stuck at 1. Every subsequent call throws **"recursive use of an object detected"** until page reload. Fix: return `String` via `serde_json::to_string` (pure Rust); `JSON.parse` on the JS side. `web_time` is the non-obvious offender — replace with a count-only stat or move timing to the JS caller.

## WASM-Bridged Structs

`Option<T>` fields need `#[serde(default)]` — `serde` errors on absent JSON keys (not null, but absent). JS callers that omit optional fields cause `serde_wasm_bindgen::from_value` to fail for the whole batch.

## wasm-core Architecture

- **Rust parity validators**: belong in `wasm-core/tests/` as standalone integration test files — compile only during `cargo test`, zero production binary weight. Examples: `pattern_matcher_parity_test.rs`, `two_phase_test.rs`. A test of a `pub(crate)` function lives in its module instead, reading a shared `test-fixtures/*.json` (conflict resolution, tokenizer).
- **`detect_hierarchical_composition` requires token range containment before substring check** (`two_phase.rs:479`): always verify `phase_a.start_index >= phase_b.start_index && phase_a.end_index <= phase_b.end_index` before `.contains()` — fires falsely on disjoint spans sharing common Vietnamese words.
- **`process_phase_a` must combine literal-starting AND variable-starting candidates** (`two_phase.rs`): hoist `variable_patterns` outside the loop and extend both slices each iteration. Fallback-only logic silently skips variable-starting Phase A patterns wherever a literal-starting one also exists.
- **Variable-before-variable span: take the SHORTEST valid span** (`matcher.rs:resolve_variable_with_lookahead`): `candidateSpans` is ordered longest→shortest; do NOT break on the first hit — let shorter spans overwrite `result` so the final value is the shortest. Taking the longest greedily exhausts tokens the next variable needs.
- **WASM `translationSource` strings in `two_phase.rs` must match JS `PHASE_PRIORITIES`**: `from_match_result()` emits `"hierarchical_pattern"` (Phase A) and `"hierarchical_patterns"` (Phase B/default). Any other string returns priority 999 in `getSourcePriority()`, ranking the token below character fallback with no error. Enforced by `src/utils/__tests__/WasmTranslationSourceParity.test.js`, which scans the production Rust for `translation_source` literals — test-module fixtures are excluded, so a value used only in `#[cfg(test)]` code is not checked.

## Tauri Command Security

- **All direct file writes must use `write_atomic(path, bytes, context)`, never `fs::write`** (`context` is the noun in the caller's errors: `"dictionary file"` or `"config file"`, so a failed appearance save does not report a dictionary failure): crash mid-write leaves a truncated/corrupt file. `write_atomic` writes to `.tmp.<pid>` then renames atomically. Applies to all commands that write files — `save_json_file` and `import_dictionaries` were the known gaps. **Confirmed twice**, both closed; a 2026-08-31 sweep found the only remaining `fs::write` in production is the one inside `write_atomic` itself. Stays prose until a third instance justifies a standing scan.
- **All `fs::*` calls must use `sanitize_io_error`, never `e.to_string()`**: exposes full OS paths to the frontend. Use `.map_err(|e| sanitize_io_error(e, "context label"))?` for every I/O call, including error strings pushed into response `Vec<String>`. Exceptions: Tauri API errors (no filesystem paths). Also applies to `zip::ZipError` (embeds filenames from ZIP headers — use static messages) and `serde_json` parse errors (can embed content snippets — use `format!("Invalid JSON in dictionary '{}'", id)`) and `serde_json` serialization errors (`to_string_pretty` can include type/value details — use `|_| "Failed to serialize ...".to_string()`). A 2026-08-31 sweep found 0 remaining `map_err(|e| e.to_string())` in this crate.
- **Tauri plugin errors** (e.g. `OpenerExt::open_path`): plugin `Display` impls may embed the path — use `.map_err(|_| "static description".to_string())`.
- **Cache keys must not embed `file_path.display()`**: `get_cache_key()` must use only `dictionary_id`. Cache keys can be serialized or logged.
- **All config.json writes must use `save_json_file()`**: enforces `check_json_depth(data, 50)` and 10MB cap.
- **New single-JSON-blob persistence** (not a multi-dict pattern): reuse `load_json_file_with_default`/`save_json_file` in `dictionary_commands.rs` — already the pattern behind config/appearance/transform-rules persistence. Don't hand-roll read/write; these already carry the atomic-write + size-cap + depth-guard hardening. Adding a 4th blob kind: add one `BlobKind` variant (with its `filename()`/`default_value()` match arms) and 2 one-line `#[tauri::command]` wrappers delegating to `load_blob`/`save_blob` — the 6 existing commands (`{load,save}_configuration`/`_transform_rules`/`_appearance_settings`) already follow this shape (architecture review 2026-09-08, candidate #2 grilling; the IPC command names/`tauriAPI.ts` surface were deliberately left untouched — see `BlobKind`'s own doc comment for why).
- **`validate_dictionary_payload(&data)` is the single guard sequence for dictionary JSON from an untrusted source**: object-check + entry-count cap (`MAX_DICTIONARY_ENTRIES`) + `check_json_depth`. Called by `save_dictionary`, `import_dictionaries` (per ZIP entry, before write), and `read_dictionary_file` (on read, since externally-written files can bypass the write-side guard). Do not re-derive this sequence inline at a new call site — add the call site here instead.
- **ZIP-bomb guard must use `.take()`**: `file.size()` from the `zip` crate is attacker-controlled. Use `file.take(MAX_BYTES as u64 + 1).read_to_string(&mut s)` then check `s.len()`. This guard is upstream of `validate_dictionary_payload` — it defends against oversized decompression before the JSON is even parsed, so it can't fold into the shared guard sequence.
- **Every command writing to `dictionaries/` must call `get_or_create_dictionary_dir(&app_handle)?`**: `get_dictionary_path` only returns the path without creating the directory.
- **`DictionaryCache.invalidate` uses exact-key match**: `get_cache_key()` returns bare IDs (`"phrases"`, `"properNouns-MyNovel"`). Do NOT introduce colon-separated key formats — it makes every targeted invalidation a silent no-op.
- **`load_dictionary_file(path, cache, dictionary_id)` is the single read protocol**: cache hit, else `read_dictionary_file` — size guard → read → parse → `validate_dictionary_payload` → `cache.set_if_current(…, generation)`, where `generation` is read BEFORE the file is touched so a save landing meanwhile stops the stale bytes being cached. It returns `Result<Value, LoadFailure>`; the only caller, `load_dictionaries_parallel_impl`, maps a failure to that id's soft `err` (`LoadFailure::message`). **A missing file is `{}`, not a failure, and is not cached** (ADR-053). The single-id `load_dictionary` command was deleted 2026-10-09 (`deleted-symbols.md`): the TS retry calls the batch command with the failed ids. Test through `load_dictionary_file`/`read_dictionary_file` against a temp dir, no `AppHandle` needed.
- **`write_dictionary_bytes(path, bytes, cache, dictionary_id)` is the single write protocol**: invalidate-before → `write_atomic` → invalidate-after. Invalidate first to close the steady-state race (a concurrent `read_dictionary_file` between write completion and post-write invalidation re-caching stale data), then again after the rename to close the rename-completion gap. Takes already-serialized bytes, not a `Value` — callers control their own byte representation. `save_dictionary` re-serializes via `serde_json::to_string_pretty`; `import_dictionaries` passes the imported file's bytes verbatim so on-disk format isn't altered by round-tripping through serde.
- **File+config atomicity**: `rename_proper_nouns_dictionary` is the only command mutating both a dictionary file AND `config.json` (create stopped writing config 2026-10-03); it must (1) read+prepare the updated `config` value in memory, (2) mutate the filesystem, (3) call `save_json_file`. On `save_json_file` failure, roll back the filesystem op (`fs::rename` back) so file and config never diverge. File-first ordering leaves config dangling on serialize/depth-guard failure. A config that exists but cannot be read or parsed refuses the rename before anything moves (a missing one proceeds), and a failed config restore during cascade rollback is reported in the error, not swallowed (2026-10-06).
- **`Result<DictionaryResponse, String>` has two failure channels, don't conflate them when composing `_impl` fns**: `Ok(DictionaryResponse::err(...))` is soft — the caller keeps running or owns its own rollback around it; `Err(String)` is hard — it aborts immediately via `?` and skips any caller-side rollback. This is why `rename_proper_nouns_dictionary_impl`'s cascade can't just call `rename_structural_patterns_dictionary_impl` directly (see the `collision_message` entry below) — the callee's `Err` would skip the cascade's own rollback entirely. Check which channel a callee actually uses before delegating to it.
- **`collision_message(new_path, new_dictionary_id, label)` is the rename-target-exists check** for `rename_proper_nouns_dictionary_impl`'s paired-patterns cascade. Added 2026-09-09: the cascade previously called `fs::rename` on the patterns target with no pre-check, so an existing `patterns-<suffix>.json` was silently overwritten instead of rejected. It was shared with the standalone `rename_structural_patterns_dictionary_impl` until that command was deleted (2026-10-07, no caller); the cascade has its own rollback (undo the properNouns rename + reverse the config substitution), so the check stayed a helper, not a whole shared rename body.
- **Best-effort side effects must report true post-op state, not assumed success**: a command whose secondary write is "best-effort, non-fatal on failure" (e.g. the `activeProperNouns` append `create_and_activate_proper_noun_file` used to do; create no longer writes config at all, 2026-10-03) must re-read and return the real result (`DictionaryResponse::ok_with_dicts(...)`), not a bare `ok()` the caller has to assume from. Found twice (2026-08-07, architecture review candidates #2/#3): rename's `defaultQuickAddDictionary` swap gap, and create's checkbox-lies-until-clicked bug — both from a TS caller trusting an interface that didn't say what actually happened.
- **The crate is not rustfmt-clean — never run `cargo fmt`.** `cargo fmt --check` reports diffs in 8 files (`dictionary_commands.rs` 144 hunks, 2026-10-03), so a crate-wide format rewrites code you didn't touch. Match the surrounding style by hand.
- **A poisoned cache lock is cleared and un-poisoned on first use** (`LruCache::lock`, ADR-068), so `record_mutex_poisoning` fires once per panic. Do not add a second `Mutex` to a cache: two locks are what the phantom-entry and eviction patches were for.
- **`emit_poisoning_event()` is the only valid path for cache-poisoning notifications**: calling `app.emit(...)` directly bypasses the 60-second rate limiter.
- **`lookup_index_engine` (this crate, native, Tauri IPC) and `wasm-core` (browser WASM) define separate same-named/same-shaped types — never conflate them.** Confirmed instances (`wasm-core` had its own `TrieNode` and `DictionaryEngine` until 2026-10-04, ADR-073): `TrieNode` (`lookup_index_engine::TrieNode` has `pub fn insert(word, translation, metadata)` — do not write manual `for ch in word.chars()` traversal loops; it's the one that matters for translation speed, rayon-parallel, real hot path for text ≥50 chars, see ADR-040) and `DictionaryMatch`'s `end_pos`/`start_pos` fields (this crate's `DictionaryMatch` is consumed only via `MatchSource.ts`'s index adapter, which never reads `end_pos`).
- **`src-tauri/benches/` exists as of 2026-08-20** — `cargo test` does not compile benches, so CI runs `cargo check --benches` for both crates. Bare `cargo check` also skips `#[cfg(test)] mod tests` — a test-signature break stays invisible until `cargo check --tests`/`cargo test`.
- **One-off timing measurement from a `harness = false` bench**: `cargo test --bench <name>` does NOT run `#[test]` fns in these — `harness = false` disables the test harness, so it runs the criterion `main()` (the full suite) instead. To get an isolated number, temporarily swap `criterion_group!`/`criterion_main!` for a plain `fn main() { ... }` that does the one measurement, `cargo bench --bench <name>`, then `git checkout -- <file>` to revert.
- **LRU behavior is `lru_cache.rs`'s contract, tested there.** Recency is a counter under the one lock (ADR-068), so ties cannot happen and a test may assert _which_ key was evicted. `DictionaryCache`/`TrieCache` tests only check their own cap and `invalidate`; neither wrapper exposes recency, so do not reach for it.
- **Testing `#[tauri::command]` fns**: if the only `AppHandle` use is path resolution, extract a thin wrapper (resolve path, +dialog if any) that delegates to a `fn X_impl(dictionary_path: &PathBuf, ...)` — directly testable via the `temp_test_dir()`-style temp-dir helper in `dictionary_commands.rs`'s `mod tests`, no `AppHandle` mock needed. Dialog-based commands (file pickers) need the dialog-picked path threaded through as an `_impl` param too. Same split applies when the blocker is `State<'_, T>` instead of `AppHandle` (e.g. `DictionaryCache`) — keep the State-gated check in the thin wrapper, pass the rest as plain borrowed params. If the extracted `_impl` has no filesystem I/O, it needs no `temp_test_dir()` — construct fixtures directly and call it (see `build_lookup_index_impl`, 2026-07-17e).
- **`DictionaryResponse` has no `#[derive(Debug, PartialEq)]`** — `assert_eq!(result, Err(...))` and `result.unwrap_err()` both fail to compile on a `Result<DictionaryResponse, String>` (`unwrap_err` also requires the `Ok` type to be `Debug`). Use `match result { Err(e) => assert_eq!(e, "..."), Ok(_) => panic!(...) }` instead.
- **`hashbrown::HashMap` + rayon parallel `collect()`**: `hashbrown` doesn't implement `FromParallelIterator` — `.collect()` on a `ParallelIterator` of `(K, V)` won't compile. Use `.collect::<Vec<_>>().into_iter().collect()` instead. Affects `lookup_index_engine.rs::build_index_parallel`.
- **A command doing real work over `State<Mutex<T>>`'s content (a multi-pass scan, not a slice) must take a handle out and release the lock before computing** — `cache.with_current(|c| ...)` for the whole computation blocks every other command sharing that Mutex (e.g. `read_book_lines`) for as long as the scan takes. The cached book is an `Arc<BookContent>`: clone the `Arc` inside the lock (zero-copy, still valid if `open_book` replaces the book mid-scan), then compute lock-free. `book_commands.rs`'s `pub(crate) fn open_book_handle` is the one seam for this — `chapter_outline_commands.rs`'s `detect_chapter_outline_impl`/`chapter_headers_for_pattern_impl` call it rather than touching `BookCache`'s internals (`CachedBook`, `with_current`) directly, which stay private to `book_commands.rs` (split 2026-09-19, architecture review candidate #4 grilling — the module doc comment previously undersold `book_commands.rs`'s scope as "four thin commands" when it held 7, two of them a different concern with no matching file). Test fixtures follow the same seam: `book_commands::tests::cache_with_open_book` is `pub(crate)` and reused by `chapter_outline_commands.rs`'s own tests rather than duplicated.
- **Local and CI share `-D warnings` (`.cargo/config.toml`) but not the OS.** An item whose only caller sits behind `#[cfg(target_os = "macos")]` is dead code on CI's Linux and fails there alone — gate the item with the same cfg. Hit 2026-10-03: `webview_diagnostics.rs`'s `TERMINATIONS` and `on_web_content_terminated`.
- **A `tauriAPI` wrapper proves nothing about use: `IpcCommands.parity.test.ts` demands one for every registered command.** Count callers excluding `tauriAPI.ts`, `lib.rs`, the command's own tests and `.d.ts` (`reset_dictionaries` sat with none for months, deleted 2026-10-07, `deleted-symbols.md`).

## Reader Corpus Tests

**Matching a `read_dir`-returned file name against a literal string is normalization-sensitive on macOS.** `read_dir().file_name()` comes back NFD (diacritics decomposed); a Vietnamese-titled literal typed in source is NFC — byte `==` silently fails even though `Path::join(literal)` + `is_file()`/`read()` succeed fine (APFS path lookups are normalization-insensitive, string equality isn't). Match on a CJK-only substring instead — CJK characters have no decomposition, so they compare equal in both forms. Hits any corpus test keyed by filename (`book_loader.rs`, `chapter_outline.rs`) and a shell `ls | grep` of the library alike — search it by the Chinese title.

**`SKIP_READER_CORPUS_TESTS=1` is not a green corpus run** — the library grows (23 → 33 → 55 books by 2026-09-29) and both corpus tests assert the count _before_ any per-book check, so "corpus size changed" hides every real mismatch behind it. Run plain `cargo test` before reporting Rust green after touching `book_loader.rs`/`chapter_outline.rs`; when the count moves, probe every book with a temporary non-panicking loop (print elected vs expected) and classify each mismatch — a wrong expectation, a real election bug, or an unsupported heading — before editing; a CJK title key can catch a new title (`修`+`真` matched `修真聊天群`; now `世`+`界`).

**A change to chapter election reaches only books never opened** — `books.json` caches each book's `chapterOutline` (no version stamp) and a reopen skips election; before calling an election fix done for the user, check their `books.json` (read-only, `dangerouslyDisableSandbox`) for the affected titles' cached `pattern`, and say which books would need their record's outline cleared.
