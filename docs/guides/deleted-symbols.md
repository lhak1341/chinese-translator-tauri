# Deleted Symbols

Split out of `development.md` 2026-09-07 (agent-config-hygiene restructure) — this registry is a distinct concern (what's already been removed, and why) from a general development guide, and had grown to dominate that file's line count.

**Check this file before recreating anything that looks missing.** Each entry records a real investigation (caller count, ADR reference, or a traced bug) — re-deriving the same conclusion from scratch costs real time; this is the shortcut.

## Historical / Deleted {#deleted-symbols}

**The TS `TranslationEngine` interface cut to what callers use, ten orphaned types and `Translator.jsx`'s `@import` block deleted (2026-10-07, architecture review round 18, candidate #2)**: `src/types/TranslationEngineTypes.d.ts`'s `TranslationEngine` interface declared five methods the class does not have (`performEmergencyCleanup`, `performHighPriorityCleanup`, `startMemoryProfiling`, `completeMemoryProfiling`, `getSmartMemoryStats`; each is already recorded elsewhere in this file) plus `isInitialized`, `settings`, `activeProperNouns`, `translationSegments`, `semanticArrayBuilder`, `syncDictionaries`, `getEngineStats` and `translateWithProgressiveBatches`, none of which any code outside the engine reads or calls. It is now `initialize`, `isReady`, `destroy`, `translateWithSegments` and `translateWithCharactersOnly`. Deleted with it: `EngineStats`, `PerformanceStats`, `TextSizeCategory`, `VirtualizationThresholds`, `HighlightingState`, `HighlightingAction`, `ScrollPosition`, `SavedScrollPositions`, `StreamingTranslationState` and `ProgressInfo` (each unused, or duplicated by a local definition in a hook, reducer or component), and the `@import` block at the top of `Translator.jsx` that imported 13 names the file never used, one of which (`AdvancedPerformanceStats`) existed nowhere. The class methods `syncDictionaries` and `getEngineStats` stay (ADR-021 keeps `getEngineStats`; `syncDictionaries` was deleted 2026-10-08, see below). `src/types/engineConformance.ts` now makes `tsc` fail if the interface names a member the class lacks; it checks names only, since the class's JSDoc says `Promise<Object>` where the interface says `Promise<TranslationResult>`. No ADR: nothing was measured or debated.

**`TranslationEngine.findAllMatches` deleted (2026-10-04)**: an async pass-through to `dictionaryManager.findAllMatchesAsync` with two callers. `getCandidateMatchesAtPosition` calls the dictionary manager directly; `processRemainingPhrases` (now synchronous) calls the sync `dictionaryManager.findAllMatches(…, ['phrases'])`, which cannot reach the WASM tier, so the phrase pass no longer depends on `WASM_MIN_DICTIONARIES` staying above 1. **`ParallelConfig` and `ReadonlyOptimizationUtils` deleted (2026-10-04)**: the engine fed `adaptToDevice` `maxTokens * 50` (about 750 KB) where it expected bytes of device memory, and macOS has no `performance.memory` to feed it honestly, so it always set `chunk.enabled = false`. Its module singleton also made `translateWithProgressiveBatches`'s initial batch size depend on call history (5 on the first large translation in a process, 3 after). The initial size is now the constant `MIN_BATCH_SIZE`, and `AdaptiveBatchSizer` grows it toward `MAX_BATCH_SIZE`. Also gone: `engine.parallelConfig` (read only as an init guard), `initializeParallelProcessing`, `_initialBatchSize`, `ParallelConfig.test.js` and the `_initialBatchSize` block of `TranslationEngine.regression.test.js`. The `'dictionary'` branch was always `enabled: true`, so `processRemainingPhrases` stopped branching on it. The same day the two phrase implementations behind it were merged: `processRemainingPhrasesParallel`, the `processRemainingPhrases` wrapper that picked between them (`tokens.length > 10`), and `PHRASE_PROCESSING` (`BATCH_SIZE`, and `PARALLEL_THRESHOLD`, which the engine never read) are deleted; `processRemainingPhrasesSequential` is now `processRemainingPhrases`. Evidence: 400 random token arrays (314 with matches) gave identical tokens and semantic arrays from both, the lookup was a single-dictionary search that never takes the WASM tier, and the parallel path's extra `priority` field is unread by conflict resolution. It was also about 25% slower at 20,000 tokens (about 31 ms against 24 ms). Its `Promise.all` batches over synchronous lookups gave no concurrency. `scanTokens` had one caller, which already carried the same loop in its `catch`; it is a plain loop now.

**Deleted symbols — do not recreate:**

- **`DictionaryManager`'s lazy tier (`filterActiveDictionaries`, `getPendingDictionaries`, `pendingDictionaries`, `lazyLoadDictionary`, `getLazyLoadingStats`), its `getCacheStats`/`getCacheMemoryUsage`/`setCacheEnabled`/`getSortingStats`, and `TranslationEngine`'s `getCacheStats`/`getCacheMemoryUsage`/`getLazyLoadingStats`/`setCacheEnabled` pass-throughs** (deleted 2026-09-30, architecture review candidate #2): the engine's only caller filtered inactive proper nouns before the manager saw them, so the manager's second filter never removed anything and nothing was ever pending; none of the getters had a caller. `TranslationEngine.initialize` now calls `filterDictionariesForEngine` itself. The engine's own pre-warm called `this.translationCache`, a field nothing assigned, so it threw a TypeError caught as a WARN on every init. `TranslationCache` is now the lookup memo alone. Do not recreate a pre-warm without measuring first-translation latency.
- **`ParallelConfig`'s `updateConfig`, `resetToDefaults`, `adaptToPerformance`, `validateConfig`, `exportConfig`, `importConfig`, `deepMerge`, its `performanceHistory` and the `monitoring` / `fallback` config sections and unread keys (`chunk.memoryThreshold`, `batchSizeMultiplier`, `fallbackTimeout`, `dictionary.lookupTimeout`, `retryAttempts`); `TranslationEngine`'s `this.parallelConfig.enableParallelChunks` / `chunkParallelThreshold` / `memoryThreshold` / `fallbackToSequential` and the "forcing parallel processing" check in `processChunksInParallel`; `ReadonlyOptimizationUtils`' `applyTokenUpdates`, `createTokenUpdate`, `findUnprocessedTokens`, `findConsecutiveUnprocessed` and their types; benchmark #10 in `OptimizationBenchmarks.js`** (deleted 2026-10-03, architecture review candidate #2): zero production callers. The engine had removed the sequential fallback but kept computing the decision and logging a WARN that it was overridden; chunks in a batch always run in parallel. `ParallelConfig` keeps `getConfig`, `adaptToDevice` and `getOptimalConfig` (covered by `ParallelConfig.test.js`); `ReadonlyOptimizationUtils` keeps `scanTokens`. `TranslationProfiler` and the memory profiler stack were checked and kept: the profiler is wired around all five phases (dev console `enableProfiling()`), and `ComponentMemoryProfiler` times `SmartMemoryCoordinator`'s cleanup callbacks.
- **`AdaptiveChunker.js` (the module and its `adaptiveChunker` singleton: `analyzeContentCharacteristics` and its density/variance helpers, `determineChunkingStrategy`, `calculateOptimalChunkSize`, `recordPerformance`, `reset`, `analyzePerformanceTrend`), its export from `text/index.ts`, `TranslationEngine`'s `memoryUsage` probe that fed `recordPerformance`, the "Smart chunk sizing" log, `_clampInitialBatchSize`** (deleted 2026-10-03, architecture review candidate #2's "found, not fixed" grilling; replaced by `_initialBatchSize(chunkConfig)`): `calculateOptimalChunkSize` always returned a size in [8, 20] (`minChunkSize` 8, `maxChunkSize` 20), and `_clampInitialBatchSize` capped it at `maxParallelChunks` (at most 5, or `MIN_BATCH_SIZE` 3 when chunking is off), so the initial batch size never depended on it. Do not rebuild adaptive initial sizing without first deciding that batches of 8-20 are wanted: `AdaptiveBatchSizer`'s shrink guard assumes 3-5.

- **The `check_dictionary_cache_health` command, `CacheHealthResponse`, the `MUTEX_POISONED` flag, and the byte-order sort in `scan_library_impl`** (deleted 2026-10-03, architecture review candidate #4): the command was registered but nothing called it; the frontend learns of a poisoned dictionary cache through the `dictionary-cache-critical-error` event (`useCachePoisoningGuard.ts`), which `record_mutex_poisoning` still emits, rate-limited. Tauri events are not replayed, so a poisoning before the hook mounts is missed; if that ever matters, poll once on mount rather than recreating the periodic command. `scan_library` now returns books in `read_dir` order: every consumer goes through `ReconcileLibrary.ts`, whose locale-aware `byShelfTitle` is the only sort (Rust's `String::cmp` put capitals before lowercase and did not fold diacritics).
